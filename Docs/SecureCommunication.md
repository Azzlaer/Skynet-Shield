# Secure Communication — 0.5.0-alpha

Native Windows WinHTTP HTTPS POST to /v1/heartbeat on port 443. TLS 1.2 or 1.3 where supported; normal OS certificate and hostname validation, no redirects, no cookies, no proxy, no automatic authentication. Configure the host from trusted deployment configuration, never from an untrusted server response. Bearer tokens are 256-bit random session credentials and must not be logged or embedded in the binary. Client sends only a positive uint64 sequence; no personal data, memory dumps or module paths.

The Python SessionStore is an in-memory reference validator, not a listening service. Future server endpoint must authenticate the player through GameServer before issuing a token, bind token to the game session, enforce request-size and rate limits, return 204 only for accepted heartbeats, and reject all other requests. Session expiration is absolute and requires renewal; a monotonic sequence is atomically consumed per token. Lost responses may mean a sequence was already consumed; send a new sequence, never retry the same one. Revoke on logout. Multiple server workers require a shared atomic store. TLS termination and end-to-end testing are pending.

A heartbeat demonstrates possession of a token, not a clean client. A compromised client can forge its own heartbeat; enforce gameplay on the server. No automatic bans. Do not call from DllMain or the render thread. Per-operation timeouts are not a total request deadline. Windows trust store validation is not certificate pinning. Native tests cover invalid parameters only; Python tests cover replay, expiration, revocation and concurrency. No live endpoint is deployed.
