# Shield Server — v0.7.0-alpha

Python 3.10+ standard-library WSGI application with persistent SQLite session and event state. Generate two independent secrets using python -c "import secrets; print(secrets.token_hex(32))". Set SHIELD_GAME_KEY and SHIELD_ADMIN_KEY privately in the environment and SHIELD_DB to a protected database path outside the checkout. Run python -m Server.run for local development on 127.0.0.1:8765. Never expose the development server directly to the internet.

For deployment use a production WSGI server behind a trusted HTTPS reverse proxy, with request size, timeout, rate and connection limits; block direct backend access. Configure the DLL with the trusted HTTPS hostname. TLS termination, proxy configuration and end-to-end tests are not included. Never log Authorization headers or response tokens.

All POST endpoints accept application/json and Bearer authentication. GameServer key: /v1/session/issue and /v1/session/revoke with {"game_session":"opaque-id"}; only call issuance after authenticating a player independently. Issue returns token and expires_in; rotating the same game session revokes its previous token. Client token: /v1/heartbeat with {"sequence":1}; /v1/events with {"sequence":2,"kind":"memory_mismatch"}. Sequences are shared across both routes. Accepted requests return 204. Admin key: GET /v1/admin/overview, returning active unexpired session count and last 100 events. Do not distribute service keys to clients. Admin key is for backend use only, not browser JavaScript.

SQLite transactions atomically consume sequences and store events, preserving state across restarts. Expiration uses wall clock; synchronize server time. Events are unverified client reports, limited to fixed categories, with bounded history of 10,000 entries (not a time-based retention policy). Session IDs should be opaque and contain no personal information. No automatic sanctions. No account or HWID collection. No per-session rate limiter in the prototype; enforce limits at the gateway before deployment. Protect DB backups and configure retention. Production authentication, key rotation, admin accounts, telemetry integration and GameServer binding remain pending.
